fix(platform): update and link the InfluxDB _internal measurements page

Closes #7557

## What changed

- Refreshed the `_internal` measurement and field reference on
  `content/platform/monitoring/influxdata-platform/tools/measurements-internal.md`.
  Added the `localStore` measurement and 25 field keys that were missing
  from the page, including the `compactionPlanner*` fields on
  `tsm1_engine`, the queue and node fields on `hh`, the `storeRead*`
  fields on `cluster`, `queryExecutor.queriesFailed`,
  `queryExecutor.queriesSlow`, `shard.writeValuesOk`, and
  `subscriber.memUsage`.
- Corrected two misspelled field names on `tsm1_wal`:
  `oldSegmentDiskBytes` is now `oldSegmentsDiskBytes`, and `writeOK` is
  now `writeOk`. Both headings and their anchors changed.
- Added a note listing six documented names that didn't appear on the
  test instance (`httpd.valuesWrittenOK`, `shard.indexType`,
  `write.pointsWrittenOK`, `write.subWriteDrop`, `write.valuesWrittenOK`,
  and the `hh_database` measurement). They stay on the page, marked as
  pending confirmation against the InfluxDB source, instead of being
  removed on the strength of a single instance capture.
- Restructured the top of the page into a short wayfinder: a
  numbered list that routes InfluxDB 3 Enterprise, InfluxDB Enterprise
  v1, and InfluxDB Cloud (TSM) readers to their own monitoring
  entrypoint, plus an "Also see" line for the remaining editions
  (InfluxDB 3 Core, Cloud Dedicated, Cloud Serverless, Clustered, and
  2.x). The detailed `_internal` field reference below is still the
  right place to land for InfluxDB v1.x and Enterprise v1 readers.
- Added a note that InfluxDB writes `_internal` metrics by default and
  needs no configuration to do so, folding in the request from #4482
  (left open; not closed by this change).
- Added a short mention of querying `_internal` via the UI/CLI and of
  third-party compatibility through the `/metrics` Prometheus
  endpoint, alongside the existing Telegraf plugin link.
- Linked the page from both v1 monitoring pages: the "Internal
  monitoring" section of
  `content/influxdb/v1/administration/server_monitoring.md`, and the
  entrypoint list on
  `content/enterprise_influxdb/v1/administration/monitor/_index.md`.
  Neither page linked to it before.

One item from the maintainer's requested edition order is intentionally
left as a `TODO(human)` HTML comment in the page: a second InfluxDB 3
edition was supposed to rank between InfluxDB 3 Enterprise and
InfluxDB Enterprise v1 in the wayfinder list, but its name wasn't
confirmed for this run. Please fill it in (or remove the comment if it
doesn't apply) before merging.

## Why

The page was out of date and effectively unreachable. Nobody could
find it from the v1 monitoring docs, and the field list didn't match
what a current InfluxDB Enterprise 1.x instance actually reports, so
readers troubleshooting with `_internal` were working from a stale and
undiscoverable reference.

## Impact

Readers who land on this page from search now get routed to the right
monitoring docs for their InfluxDB edition instead of a v1-only page
that doesn't mention newer editions. InfluxDB v1.x and Enterprise v1
users get a corrected field reference. No URLs changed, so existing
inbound links and the page's alias still work.

## Verification

No live instance was available in this run (`AGENT_VERSION` is `none`).
The field and measurement diff was checked against a live-instance
capture from a prior run of the same investigation (InfluxDB
Enterprise 1.x, captured 2026-08-04), not re-queried live here. A live
`SHOW FIELD KEYS` / `SHOW MEASUREMENTS` re-check, and a source check of
the six unconfirmed field names against `influxdata/influxdb`
master-1.x, are still outstanding and should happen before or shortly
after merge. All new internal links were confirmed to resolve with a
local Hugo build (`hugo --quiet --gc`), including the three-item
wayfinder list, which required moving an HTML comment out of the
Markdown list to avoid truncating it during rendering.
