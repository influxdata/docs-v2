# AI visibility

How docs.influxdata.com is consumed by AI systems — crawlers building
training corpora, RAG retrievers, and autonomous agents — and how to verify
each surface from outside the build.

[DOCS-DEPLOYING.md](DOCS-DEPLOYING.md#llm-markdown-generation) covers how
these artifacts are *generated*. This file covers what is published, how it
is discovered, and how to check it. Verify `file:line` claims against
current code — this records where things lived when written, and the
pipeline evolves.

## The three Markdown artifact layers

| Artifact | Granularity | Generated by | Discovered via |
| --- | --- | --- | --- |
| `public/<path>/index.md` | per page | `scripts/build-llm-markdown.js` | `<link rel="alternate" type="text/markdown">`; `/sitemap-md.xml` |
| `public/<path>/index.section.md` | section (page + descendants) | `scripts/build-llm-markdown.js` | `/llms.txt` section entries |
| `public/<product>/llms-full.txt` | product (flattened corpus) | `scripts/build-llms-full-txt.js` | `/llms.txt` "Full corpora" block |

`llms-full.txt` is published **per product** (for example
`/influxdb3/core/llms-full.txt`). The root `/llms-full.txt` is
intentionally 404 — don't report it as a gap.

## Eligibility predicates (three surfaces, kept coherent)

The same eligibility logic is mirrored in three places; drift between them
is a findable bug class:

- `layouts/partials/header/markdown-alternate.html` — emits the head link
  (kind is page/section, not `omit_from_sitemap`, not `noindex`, not
  feature-board layout).
- `layouts/sitemap-md.xml` — twin URLs in the markdown sitemap.
- `scripts/lib/corpus-paths.js` — derives the corpus list from
  `data/products.yml`.
- `scripts/check-md-alternate-coherence.js` (`yarn check:md-coherence`) —
  the guard that verifies the surfaces agree. Runs on master and staging
  deploys, skipped on partial PR builds.

## The products.yml gate

`getCorpusPaths()` skips any product in `data/products.yml` without a
`content_path`. A product missing `content_path` gets **no `llms.txt`
entry and no `llms-full.txt` corpus**, even when its pages have working
twins, head links, and sitemap-md entries. Telegraf Controller was
excluded this way (tracked in influxdata/docs-v2#7320). When a product is
"invisible to llms.txt," check `content_path` first — the fix is data,
not code.

## JSON-LD entity graph

Partials in `layouts/partials/header/*-jsonld.html` emit:

- `Organization` (site-wide, stable `@id`)
- `SoftwareApplication` on product roots (name, `softwareVersion`,
  applicationCategory)
- `TechArticle` on doc pages, with `about`/`isPartOf` pointing by `@id` at
  the product root's `#software` node
- `FAQPage` where FAQ blocks exist

Validate with `validator.schema.org`, **not** Google's Rich Results Test —
Organization/TechArticle/SoftwareApplication aren't rich-result types and
the Rich Results Test false-negatives on them (see
[DOCS-TESTING.md](DOCS-TESTING.md), "Structured Data (JSON-LD)
Validation").

## Verifying a surface

Fetch, don't assume. Two gotchas produce false findings:

- **Always `curl --compressed`.** Production serves gzip; raw bytes look
  like binary garbage and a naive fetch "finds" nothing.
- **Minified HTML drops attribute quotes.** `grep '<link rel="canonical"'`
  misses `<link rel=canonical ...>`. Match with quote-tolerant patterns
  (for example `<link[^>]*canonical[^>]*>`) or you will report present
  metadata as missing.

Useful targets:

- `https://docs.influxdata.com/llms.txt`
- `https://docs.influxdata.com/sitemap-md.xml`
- `https://docs.influxdata.com/<path>/index.md` (twin)
- `https://docs.influxdata.com/robots.txt`

## PR preview: known artifacts, not bugs

The preview workflow (`.github/workflows/pr-preview.yml`) deploys **only
the pages listed in the PR body** to
`https://influxdata.github.io/docs-v2/pr-preview/pr-<N>/`. Expect these
preview-only artifacts:

- `<title>` renders the product name as `<nil>` (path-based product
  resolution breaks under the preview path prefix).
- Canonical URLs double the path prefix.
- Mixed link bases (some site-root-relative links 404 inside the preview).
- **No Markdown twins** — the advertised `index.md` head links 404. Twin
  fidelity can only be checked on production or a staging build.

If a finding reproduces only under the preview prefix, it is a preview
limitation; verify against production before reporting it as a content or
template bug.

## Reviewing a change for AI visibility

The `ai-visibility` skill in
[.agents/skills/ai-visibility](.agents/skills/ai-visibility/SKILL.md) walks
a PR, page, or product through the discovery paths and the four consumption
layers (training corpus, post-training, RAG retrieval, agent harness) and
produces an evidence-backed report.
